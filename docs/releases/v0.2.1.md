Administrators can now inspect and edit the compiler and analyzer prompts from **Models → Edit prompts**.

### Prompt management
- Edit the complete system and request templates for rule compilation, policy splitting, analysis, optional policy screening and blocked-request rewriting: 18 templates, with the active format identified.
- Save custom instructions, inspect the required variables and response contract, or restore a shipped default. Drafts survive navigation within the same browser tab; concurrent edits preserve both versions for explicit resolution.
- Keep one prompt revision throughout each operation, including a split and its compiled rules or an analysis and all its windows. Edits apply to subsequent work.
- Store private installation-wide overrides atomically. Audit changes using revision and content hashes without copying prompt-template text into the log.

### Verification
- Fifteen isolated regression suites cover the existing product and the new prompt configuration surface.
- Fifty captured prompt hashes verify that shipped defaults and restored defaults remain byte-for-byte unchanged. New tests exercise all 18 runtime template paths, authorization, persistence, conflicts, literal substitution, bounded expansion and corrupted-state handling.
- Nineteen console tests and desktop/mobile browser workflows cover validation, saving, restoration, keyboard submission, retained drafts, concurrent editing and delayed refresh responses.
- Bench results now identify the effective templates and cannot reuse cached answers from different prompt text.

Template validation preserves required context and response contracts; it does not certify policy accuracy. Custom instructions can increase missed violations or false positives. Existing schemas, isolation, policy ratification, rewrite gates and verdict aggregation remain in code. See [prompt management](https://github.com/Wardenlabs/warden/blob/main/docs/PROMPT-MANAGEMENT.md) for scope, API, storage and evaluation guidance.
