Warden can now inspect documents submitted with employee requests, and administrators can manage both model roles from one Models screen.

### Documents
- Read PDF, DOCX, TXT, Markdown, CSV and supported images locally, including scanned and mixed PDFs with bundled English and Spanish OCR.
- Attach files in the Simulator, OpenAI-compatible proxy or supported hook payloads; see per-file reading status in the decision and Activity.
- Hold unreadable, partial, unsupported and oversized documents. Screen complete extracted text against applicable rules and forward only inspected, masked text through the proxy.
- Native tool coverage depends on the attachment bytes or explicit file references exposed by that tool. Text-only hook events cannot expose hidden files.

### Model management
- Inspect and change the compiler and local analyzer in personal and team installations.
- Keep named compiler endpoints and custom GGUF weights in an installation-wide library. Import by upload, local gateway path or HTTPS download, with progress and cancellation.
- Require a compatibility test for each role before activation, coordinate changes with in-flight requests and preserve the previous working selection on failure. Compiler endpoints may be remote; employee judging remains local.

### Verification and documentation
- Fourteen isolated regression suites cover extraction/OCR, malformed content, hooks, proxy forwarding, authentication, model changes, concurrency, credentials, and console behavior.
- Packaged desktop smoke checks exercise real PDF extraction and offline OCR under Electron. Desktop and narrow-screen browser workflows were checked interactively.
- Added API, architecture, contributor, security and third-party license documentation, plus reproducible real-model document observations.

Compatibility tests establish that a model can load and answer in the required format; they do not certify policy accuracy. OCR is conservative and may hold decorative or low-confidence images.
