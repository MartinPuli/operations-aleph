# Warden 0.2.3 — Complete queued document checks

Documents with several rules could be read successfully and then held because
every model check shared a 25-second deadline. The local runtime serializes
model calls, so checks often expired before they had a chance to run.

- Document checks now enter the model one at a time, with a fresh generation
  budget on admission and a bounded overall review deadline.
- All applicable rules and document windows remain covered. Incomplete checks
  stay held; cancelled or late model output cannot approve a request.
- The console distinguishes reading/OCR results from policy-analysis timeouts
  and explains why larger reviews can take a few minutes.
- Updated hooks use the document deadline advertised by the gateway. Re-run
  the connection setup to update previously installed hooks and host timeouts.

Validation includes real offline image and PDF OCR, queued-workload and native
cancellation regression tests, hook/proxy boundaries, and a synthetic four-page
document checked against eleven rules using local DynaGuard 8B. These are
processing and regression checks, not a general accuracy benchmark.
